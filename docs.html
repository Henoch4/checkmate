Game rules

The contract is a wager escrow + move log, not a chess engine. It never validates moves — it records the SAN you claim and the FEN you say results from it:

createGame(opponent, fen)  +value W   creator(White) escrows W
joinGame(id)       +value W   opponent(Black) matches W → game live
submitMove(id, san, fenAfter, isMate)
    requires joined, your turn, not finished
    records san + fenAfter, flips toMove
    if isMate → finished, winner takes 2×W
cancelGame(id)     White only, before join → refund W
resign(id)         either player → opponent takes 2×W
claimTimeout(id)   no move for 24h → side to move loses

Because both stakes are escrowed up front, the winner-takes-2× promise can't be broken by either player. A dishonest SAN is still visible to everyone in the event log — play honest or your opponent (and the explorer) will see it.

Reconstructing a game

Replay MoveSubmitted events in order from the initial FEN: every event carries (gameId, by, moveIndex, san, toMoveAfter), and the contract's games(id).lastFEN is the authoritative latest position.

Demo activity

Six demo transactions executed after deployment — all status ok, all methods decode by name on the explorer. The demo game is the four-move fool's mate: White (creator) opened f3, Black answered e5, White played g4, and Black delivered Qh4#.

#MethodActorDescription
1createGameWallet A · WhiteChallenge with 0.1 BOT wager, standard start FEN
2joinGameWallet B · BlackMatches the 0.1 BOT wager — game goes live
3submitMoveWallet A1. f3
4submitMoveWallet B1… e5
5submitMoveWallet A2. g4
6submitMoveWallet B2… Qh4# — checkmate, Black collects 0.2 BOT

Each project contract carries 7 explorer transactions total: 1 deploy + 6 demo. The finished game #0 is visible live in the app.
